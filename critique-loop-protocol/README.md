# 🔄 Critique Loop Protocol

A disciplined **draft → critique → revise** workflow for outputs where quality matters more than speed.

---

## Why this skill exists

Some work should not be one-shot.

If the output affects:
- money
- public reputation
- strategy
- model evaluations
- irreversible decisions

…then a critique loop is often worth the extra latency.

This skill explains when to use that loop, how to run it, and when not to waste time on it.

## The protocol

### 1. Draft
Generate the first serious version. Not a placeholder. Not a brainstorm dump.

### 2. Critique
Review the draft adversarially:
- what is weak?
- what is unclear?
- what is missing?
- what sounds smart but is actually soft?

### 3. Revise
Improve the work using the critique.
Not cosmetic patching. Real strengthening.

## When to use it

Use critique loops for:
- strategic docs
- public writing
- expensive decisions
- benchmark claims
- high-stakes plans

Skip them for:
- trivial edits
- routine code patches
- low-stakes chat
- work where speed matters more than polish

## Why this matters

Without a protocol, “let’s review this” becomes vague and performative.
With a protocol, the second pass has a real job.

## Limitations

- unnecessary for small tasks
- weak critiques create fake rigor
- the protocol helps quality, but only if the reviewer is willing to actually disagree with the draft
